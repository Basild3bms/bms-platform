# Flutter architecture

`ApiOrigin.resolve` chooses a local Android emulator origin or host loopback for other development platforms. A `BMS_API_BASE_URL` compile-time override accepts HTTPS, while HTTP is limited to local development hosts; release configuration must be explicit HTTPS. The overview offers an on-demand check of the public status endpoint and labels it as process responsiveness only. Android debug permits cleartext only for local emulator and loopback destinations; release network security configuration denies cleartext for all destinations, including localhost. On 2026-11-18, the Windows Android 17/API 37 emulator ran the updated debug APK and the overview reported **API process reachable**. This validates the public status path from that emulator, not authentication or building data.

`lib/main.dart` starts a Riverpod `ProviderScope`. `lib/src/app.dart` configures Material UI, GoRouter, English/French locales, and light/dark themes, and starts session restoration. The `core` directory owns networking, secure storage, localization, routing, theme preferences, and shared widgets. `features/auth` owns typed API models, repository, session controller, login, startup, and organization selection. `features/shell` owns common navigation, while `features/overview` and `features/settings` own their screens. New features should live under `features/<feature>` with their own models, providers, screens, and tests.

The overview links to the read-only Buildings list and still says that no live building data is available. Equipment, live monitoring, alarms, automation, energy, maintenance, and profile routes display a reusable unavailable state. Settings can change language and theme for the current process; preference persistence is a later feature. No screen renders mock telemetry as live data.

The public Dio client calls status and login without a bearer; the protected client adds `Authorization: Bearer` for `/auth/me`, `/auth/organizations`, and Buildings GETs. Logout explicitly sends the token being revoked. `TokenStore` keeps token, expiry, and selected organization ID in platform secure storage, never passwords. On startup the controller rejects expired records, validates `/auth/me`, and fetches current memberships before protected navigation opens. A 401 clears session state; a transport failure shows retry while access stays closed. The organization picker uses only server-returned memberships. Selection is revalidated on restoration, and switching refreshes discovery, clears prior context, cancels requests, and advances a generation counter. The Buildings controller captures that context, cancels pending requests and clears records on switch or logout, and rejects stale responses. It validates each returned building's organization ID. The list uses numbered pages and pull-to-refresh; detail is read-only. Laravel remains the authorization authority.

GoRouter guards deep links and browser/back navigation across startup, login, selection, and protected routes, including building detail. The dashboard exposes overview, buildings, equipment, monitoring, alarms, energy management, reports, and settings. Unimplemented modules show unavailable states. Logout immediately closes protected navigation, clears local state, and attempts both secure deletion and server revocation; failures are surfaced to the user. M2.2B Android building runtime validation remains pending.

All equipment writes remain subject to server authorization and a separate disabled-by-default edge gate. Mobile clients never communicate with a building network directly. Release blockers listed in `SECURITY.md` and `M2_1_SECURITY_AUDIT.md` still apply.

Dependency versions resolved with Flutter 3.50.0: `material_ui` 1.11.1, `flutter_riverpod` 3.5.0, `dio` 5.11.1, `go_router` 18.1.4, and `flutter_secure_storage` 11.2.0. The secure storage plugin's Android module requires API 24, which sets the app minimum. The lockfile records the complete dependency graph.
