# Flutter architecture

The supplied Windows Android report for M2.2C.3 commit `9d94787` confirms the read-only building → floor → zone flow on `emulator-5554`, including three floors, a negative basement level, basement zone detail, navigation back through the hierarchy, Floors refresh, offline error/recovery, French labels, dark theme, and logout/back/reopen protection. It also records a successful debug APK build and 105 passing Flutter tests. iOS runtime, two-organization switching, and release-mode performance remain unverified; startup skipped-frame warnings were observed. The secure-storage commercial-release blocker is unchanged.

M2.2C.3 adds read-only Floors and Zones beneath Building Details. Each feature has typed models, protected GET client, repository, controller, list screen, and detail screen. Shared hierarchy support parses pagination and safe error categories; models validate the selected organization, all parent IDs, and requested detail ID. Signed floor levels and the contracted zone-type enum are parsed strictly. Controllers hold a session context and active parent scope, cancel superseded or abandoned requests, reject late responses, and clear protected state on organization changes or logout. Hierarchy deep links use the session router guard. Lists support pagination and refresh, with English/French labels.

The final source audit added `ref.mounted` checks before asynchronous results touch provider state, restores a usable list after canceled pagination, and reloads a visible route if a newer stacked route replaced its parent scope or detail ID. API clients reject malformed UUID paths before sending a request; list parsing rejects inconsistent metadata and duplicate records, while controllers reject duplicates across pages. An overlapping page leaves existing records visible and offers retry. These checks do not replace Laravel authorization or Android/iOS runtime validation.

`ApiOrigin.resolve` chooses a local Android emulator origin or host loopback for other development platforms. A `BMS_API_BASE_URL` compile-time override accepts HTTPS, while HTTP is limited to local development hosts; release configuration must be explicit HTTPS. The overview offers an on-demand check of the public status endpoint and labels it as process responsiveness only. Android debug permits cleartext only for local emulator and loopback destinations; release network security configuration denies cleartext for all destinations, including localhost. On 2026-11-18, the Windows Android 17/API 37 emulator ran the updated debug APK and the overview reported **API process reachable**. That check validated the public status path only; later Windows validation of commit `66fcbbe` confirmed authenticated Buildings list and detail against local PostgreSQL data.

`lib/main.dart` starts a Riverpod `ProviderScope`. `lib/src/app.dart` configures Material UI, GoRouter, English/French locales, and light/dark themes, and starts session restoration. The `core` directory owns networking, secure storage, localization, routing, theme preferences, and shared widgets. `features/auth` owns typed API models, repository, session controller, login, startup, and organization selection. `features/shell` owns common navigation, while `features/overview` and `features/settings` own their screens. New features should live under `features/<feature>` with their own models, providers, screens, and tests.

The overview links to the read-only Buildings list and still says that no live building data is available. Equipment, live monitoring, alarms, automation, energy, maintenance, and profile routes display a reusable unavailable state. Settings can change language and theme for the current process; preference persistence is a later feature. No screen renders mock telemetry as live data.

The public Dio client calls status and login without a bearer; the protected client adds `Authorization: Bearer` for `/auth/me`, `/auth/organizations`, and Buildings GETs. Logout explicitly sends the token being revoked. `TokenStore` keeps token, expiry, and selected organization ID in platform secure storage, never passwords. On startup the controller rejects expired records, validates `/auth/me`, and fetches current memberships before protected navigation opens. A 401 clears session state; a transport failure shows retry while access stays closed. The organization picker uses only server-returned memberships. Selection is revalidated on restoration, and switching refreshes discovery, clears prior context, cancels requests, and advances a generation counter. The Buildings controller captures that context, cancels pending requests and clears records on switch or logout, and rejects stale responses. It validates each returned building's organization ID. The list uses numbered pages and pull-to-refresh; detail is read-only. Laravel remains the authorization authority.

GoRouter guards deep links and browser/back navigation across startup, login, selection, and protected routes, including building detail. The dashboard exposes overview, buildings, equipment, monitoring, alarms, energy management, reports, and settings. Unimplemented modules show unavailable states. Logout immediately closes protected navigation, clears local state, and attempts both secure deletion and server revocation; failures are surfaced to the user. Windows Android validation confirmed logout/back/reopen protection for M2.2B; independent server-side token revocation verification remains pending.

All equipment writes remain subject to server authorization and a separate disabled-by-default edge gate. Mobile clients never communicate with a building network directly. Release blockers listed in `SECURITY.md` and `M2_1_SECURITY_AUDIT.md` still apply.

Dependency versions resolved with Flutter 3.50.0: `material_ui` 1.11.1, `flutter_riverpod` 3.5.0, `dio` 5.11.1, `go_router` 18.1.4, and `flutter_secure_storage` 11.2.0. The secure storage plugin's Android module requires API 24, which sets the app minimum. The lockfile records the complete dependency graph.
