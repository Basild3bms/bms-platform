# Database design

## M1 relational schema

| Table | Key fields and constraints | Purpose |
|---|---|---|
| organizations | UUID PK, unique slug, timezone | Tenant root. |
| buildings | UUID PK, organization FK, unique organization/code, timezone | Physical site. |
| devices | UUID PK, organization and building FKs, unique building/protocol/external ID | Equipment identity. |
| device_points | UUID PK, device FK, unique device/external ID, writable default false | Normalized point metadata. |

Laravel's starter user, cache and jobs migrations remain in place. User membership and tenant authorization are later work; no tenant data endpoint is exposed in M1. UUIDs are generated by application code, not by a database extension. PostgreSQL is the deployment database; SQLite in-memory runs the isolated M1 schema tests.

## Planned additions

M2.1 adds `personal_access_tokens`, `roles`, `permissions`, `role_permissions`, `organization_memberships`, and application append-only `audit_events`. It adds `users.is_active` with a true default so existing M1 users remain enabled during an additive migration. Memberships are unique by organization and user; a revoked membership remains inactive for audit history. Audit foreign keys restrict user or organization deletion when events reference them. The seeded roles are viewer, operator, admin, and owner. Admin and owner can view and manage users; only a member with a higher rank can grant or change a target role. No database user or default credential is seeded.

Floors, zones and rooms form a building hierarchy in M2.2. Telemetry samples carry point ID, source timestamp, ingest timestamp, value, unit, quality and sequence; partition by time and retention policy. Alarm, command, automation, energy and maintenance tables each carry organization and immutable actor context. Foreign keys and composite tenant checks must prevent a device from being attached to another tenant's building before CRUD APIs are released. Index tenant, point and time filters; test retention and restore procedures.
