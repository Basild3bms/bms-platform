# API contract

Base path is `/api/v1`; JSON uses UTF-8. The M1 endpoint `GET /api/v1/status` returns `{"service":"bms-api","version":"0.1.0","status":"ok"}` with HTTP 200. It signals process responsiveness, not PostgreSQL, Redis or gateway readiness. The machine-readable contract is `packages/contracts/openapi.yaml`.

M2.1 adds `POST /api/v1/auth/login`, `GET /api/v1/auth/me`, and `POST /api/v1/auth/logout`. Login issues a 12-hour Sanctum bearer token; logout revokes the current token. Organization-scoped user management is at `GET/POST /api/v1/organizations/{organization}/users`, with role changes and revocation at `PATCH/DELETE /api/v1/organizations/{organization}/memberships/{membership}`. The status and login routes are public; every other M2.1 route requires an active user and a bearer token. Web session identities are rejected by these API routes. Foreign or inactive organization memberships return 404; insufficient permission returns 403. There is no public registration route. A local operator can initialize an organization and owner with `php artisan bms:bootstrap-organization --name=... --slug=... --email=...`; the command prompts for a password and is unavailable in production.

Future collections will use cursor pagination and bounded filters. Mutations validate input, use idempotency keys where retries can cause effects, return stable error codes, and create audit events. Telemetry will include source timestamp, quality and unit; command responses will distinguish accepted, executed and observed outcomes. WebSocket channels and MQTT topics will be tenant scoped and separately authorized. No control endpoint exists in M2.1.
